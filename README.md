# Customer Segmentation with Clustering and Weightage Scoring

Segment 1,200 customers into actionable groups using a custom weighted RFM
score and KMeans clustering, so marketing and retention work can target
the right customers instead of treating everyone the same.

> **Dataset: synthetic.** Every customer in `data/customers.csv` was
> generated by `src/generate_data.py` (seed 42). No real customer data is
> used. All numbers in this README come from the actual run saved in
> `metrics.json` — nothing is invented.

## The problem

A retailer knows how recently each customer bought (Recency), how often
they buy (Frequency) and how much they spend (Monetary), but that raw
RFM data does not tell it who to retain, who to win back, or who to
leave alone. This project turns RFM into:

1. **One weighted score per customer (0–100)** — a single, comparable
   value score built from an explicit, justified weightage model.
2. **Two customer clusters** — found by KMeans, with the number of
   clusters chosen by silhouette score, not by guessing.

## Dataset

Generated by `src/generate_data.py` (seed `42`, reproducible):

| Field | Description |
|---|---|
| `customer_id` | `CUST-0001` … `CUST-1200` |
| `age` | 18–70 years |
| `tenure_months` | 1–60 months as a customer |
| `category_preference` | Electronics, Grocery, Fashion, Home, Beauty |
| `recency_days` | Days since last purchase (1–365) |
| `frequency` | Purchases in the last 12 months (1–58) |
| `monetary` | Total spend, $20.00–$3,702.72 |

**1,200 customers.** Overall means from the real run: recency 80.38 days,
frequency 12.20 purchases, monetary $618.67, age 38.03 years,
tenure 24.11 months.

The generator mixes four latent personas (Champions, Loyal, At-risk,
Dormant) so the data has real structure to discover. The persona column
(`_persona`) is kept in the CSV for validation only — it is **never**
used as a clustering feature.

## Weightage model

Each RFM component is first turned into a 0–100 percentile score, so
skewed spend does not dominate the result. Recency is inverted: fewer
days since the last purchase scores higher.

```
R_score = 100 - percentile(recency_days)
F_score = percentile(frequency)
M_score = percentile(monetary)

Weighted Score = 0.30 x R_score + 0.35 x F_score + 0.35 x M_score
```

| Component | Weight | Why |
|---|---|---|
| Recency | 0.30 | A real churn signal, but a single recent purchase alone does not prove value |
| Frequency | 0.35 | Repeat buying is the strongest habit signal |
| Monetary | 0.35 | Spend is the strongest value signal, equal to frequency |

Result on this run: weighted score mean **50.02**, range **3.21–98.04**,
median 50.22. The score is a ranking tool, not a prediction of future
spend — see Limitations.

## Method

1. **Generate** — `src/generate_data.py` creates the synthetic dataset.
2. **Score** — `src/segment.py` computes the weighted RFM score above.
3. **Scale** — clustering features are `recency_days`, `frequency` and
   `log1p(monetary)`, standardised with `StandardScaler`. Age, tenure
   and category are used only to profile clusters afterwards, not to
   form them.
4. **Choose k** — KMeans is run for k = 2..8. Inertia (elbow) and
   silhouette score are recorded for every k, and the best k is the
   one with the highest silhouette score.
5. **Compare** — Agglomerative clustering at the same k is run as a
   check on the KMeans result.
6. **Profile and chart** — `src/evaluate.py` profiles each cluster and
   saves the charts in `screenshots/`.

| 3 | 1418.85 | 0.3442 |
| 4 | 1128.89 | 0.3494 |
| 5 | 913.30 | 0.3280 |
| 6 | 796.01 | 0.3090 |
| 7 | 708.65 | 0.3116 |
| 8 | 627.20 | 0.3237 |

**Best k = 2, chosen by highest silhouette score: 0.3968.**
Final KMeans inertia at k = 2: **1974.67**.

Inertia falls steadily as k grows (the elbow is soft), while silhouette
peaks at k = 2 and then stays lower — the data separates most cleanly
into two broad groups. k = 4 is the next-best silhouette (0.3494) and
would give finer segments, but it was not chosen because the rule for
this project is highest silhouette.

|---|---|---|---|---|---|---|---|---|---|
| 0 — Engaged | 679 | 56.58% | 32.48 days | 17.71 | $915.74 | 67.99 | 37.89 | 24.58 mo | Grocery |

**Cluster 0 — Engaged (679 customers).** Bought about a month ago on
average, buy ~3.5x as often as Cluster 1 and spend ~4x as much.
Mean weightage score 67.99 (range within the cluster: 34.95–98.04).

**Cluster 1 — Disengaged (521 customers).** Last purchase ~143 days ago

Age and tenure barely differ between clusters (37.89 vs 38.20 years;
24.58 vs 23.50 months), so the split is driven by buying behaviour,
not by demographics — which is exactly what an RFM segmentation
should show.

## Business use

- **Cluster 0 — retain and grow:** loyalty rewards, early access, and
  cross-sell to the top category (Grocery here). These customers are
  already engaged; the goal is to keep them.
- **Cluster 1 — win back or let go:** a reactivation offer makes sense
  for the higher scorers inside this cluster (scores up to 57.30),
  while the lowest scorers (near 3.21) are unlikely to repay much
  marketing spend. Use the weighted score *inside* the cluster to
  prioritise, not the cluster label alone.
- **The weighted score** can also rank customers for any campaign
  without re-running clustering: top-decile scorers first.

## Limitations

- **Synthetic data.** Behaviour is generated from four personas, so
  results show the method works, not how real customers behave.
- **Only two clusters.** Silhouette picks k = 2, which is honest but
  coarse — a real retailer would usually want finer segments (k = 4
  scored 0.3494 and is the obvious next experiment).
- **Silhouette 0.3968 is moderate, not strong.** The clusters are
  clearly separated on RFM means, but they overlap in PCA space.
  This is a descriptive segmentation, not a classifier with a
  ground-truth label.
- **The weightage weights (0.30 / 0.35 / 0.35) are a justified
  choice, not a fitted one.** They were set from domain reasoning
  (frequency and monetary predict value best) and were not tuned
  against an outcome, because there is no observed future-spend
  outcome in this synthetic data.
- **No classification model is trained here.** Classification would
  need a labelled outcome (e.g. churned / did not churn); the next
  step is to add one and compare Logistic Regression vs Random Forest
  on it.
